# Binders 0.12.1

Chat with your agents. Write to Claude Code or to an agent that checks the board itself, and it answers in the chat, on the Mac's Agents page and in Binders for iPhone 2.3, which ships with it. You can watch a run as it works, Binders has a new look, and the Manager now manages your binders, team boards and Distill's proposals included. Replies read as Markdown, the Agents page fits the window with long conversations, and the Manager starts on a Mac whose Claude Code an organization manages.

## Chat with your agents

- Pick an agent on the Agents page and write to it: it answers in the chat, not on a card. Its chats are listed under it, with New Chat, and its cards below them.
- Claude Code: Binders starts it for the chat in a worktree of its own, with the permissions its cards have (its permission mode, its sandbox and web, Binders' board tools, and your approval before it sends, posts, buys or deletes anything). Each message carries the same session on, so it remembers the chat. You see what it's writing while it works, and Stop ends it. What you write meanwhile goes when it's done.
- An agent that checks the board itself (one you set up with its own Binders server) reads your messages with a new Binders tool, list_messages, and answers with reply_message. Until it checks, the chat says it's waiting.
- Scripts, web hooks, shortcuts and the other coding tools (Codex, OpenCode, Copilot, Antigravity) keep cards for now: pick one to see its cards and write it a new one, as before.
- Replies, the Manager's too, read as Markdown: bold and italics, inline code, bullets and numbered lists, headings, quotes and code blocks.

## Watch your agents work

- A run Binders starts, Claude Code or a coding tool (Codex, OpenCode, Copilot, Antigravity), now shows in its conversation as it goes: what it says, each step it takes (a file read or edited, a command, its tests passing or failing) with a check once it's done, an edit's lines, and its plan as a bar of steps under the card's title. It's read from Binders' own log of the run, every second while you look.
- Write to Claude Code on a card it worked on and its next run carries on the same session, in the same folder, so it remembers what it did.
- Stop, beside Open Card, ends a run that's going.

## A new look

- Graphite in the dark and white in the light, the sidebar a shade off a rounded page, a brighter violet, and titles in the system face. Primary buttons are white in the dark and black in the light.
- Agents wear avatars: their provider's icon (Claude, OpenAI for Codex, GitHub Copilot, Gemini for Antigravity, OpenCode, Cursor) or their initial, with a dot for what they're doing.
- Home opens on the day: how long your agents worked, against yesterday, a line for each through the day, who's on what, the questions waiting for you with Reply, and what's ready to check.
- The Agents page lists the conversations by binder, each with its agent and how it's going, then chats and your agents.
- Boards are open lanes with cleaner cards (who has it, how it's going and when, at the bottom) and a bar across the top that shows where the cards are. A binder's tabs are words with their counts.
- Knowledge opens with "Ask your work anything".

## The Manager manages your binders

- It does what you could: it moves cards to any column, gives them to agents (which starts them, as Give to does) or to people, and deletes them, as well as editing, closing and merging them. It does this on a team's board too, where its moves wait for the team's database as yours do.
- It reviews what Distill proposed: it lists the items still waiting, and places them on the board or puts them aside, as you would in the review.
- It writes, changes and deletes notes (not a teammate's, or one shared with the team), and makes, renames, recolours and archives binders.
- Undo Its Changes still puts everything back: a deleted card is made again, a deleted note comes back with its id, proposed items wait for review again, and a changed note goes back while nobody changed it since.
- A local model as the Manager is shown each tool in a sentence, so the longer list still fits a model that reads 8,192 tokens at once.

## Binders for iPhone 2.3

- A new Agents tab: the Manager at the top, then your agents, each saying what it's doing (answering a chat, working on a card, a card that needs you, idle). On iPhones before iOS 26 it's under Everything.
- Pick an agent that chats to open your latest chat with it; the chat menu starts a new one, goes back to an earlier one, or shows its cards. The first time a message goes to an agent as it's set up now, Binders asks you first, as Give to does.
- The Manager: ask it something, or tidy one binder or every binder. Stop a request, undo its changes once it's done, reply to carry on, and review the note edits it suggests line by line. What you ask goes to the agent with the role on your Mac: a local model stays on your Mac; for Claude Code, Binders asks you first, and a request asked of a Manager that has changed since isn't run.

## Fixes

- Clicking the Manager, an agent or a conversation on the Agents page did nothing. It now shows it, and stays picked when you go to another page and back.
- A long conversation on the Agents page pushed the page taller than the window, so its top slid under the title bar and the box to answer in was out of sight. The line under that box no longer stands taller than the window, and the page fits at every window size.
- On a Mac whose Claude Code an organization manages, the Manager wouldn't start ("This Mac's Claude Code is managed in a way that won't run with Binders' tools alone"). It now starts as card runs do there: without the limit Claude Code refuses, with a hook that lets it use the Manager's tools and nothing else, under a server name of its own, so a Binders server of yours is never taken for it. A request refused for the limit starts again once on its own. Where the organization runs only its own hooks, it says so rather than start.
- A local model as the Manager is no longer offered to the iPhone as an agent to give cards to: it takes none.
