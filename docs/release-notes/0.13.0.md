# Binders 0.13.0

Talk to your agents where they work. Pick an agent on the Agents page and its sessions open as a terminal, the way Claude Code shows them: what it says, each command and its output, each edit in red and green, and how each run ended. Write to a Claude Code run while it's going and your words go straight in. Binders for iPhone 2.4 shows the same. Coding tools can work in a folder of several repositories, agents can open pull requests when they finish, folders are a tree, and Distill stops proposing what it already has.

## The Agents page as a terminal

- The list is one row per agent, the Manager first, each saying what it's doing. Pick one for its workspace: what it is and where it works, Stop while a run goes, and a strip of its sessions, each card it works on and each chat, the running one first.
- Each session shows as a terminal, dark in both themes: your words after ›, what it says after ⏺, each tool as Bash(…), Read(…) or Update(…) with what came back under it (folded after 20 lines; click for the rest), an edit's lines in red and green, its plan, the working star while it goes, and how each turn ended ("Done in 3m 12s · $0.42"). It reads every run of the session from Binders' own logs and follows the one going.
- The prompt at the bottom talks to that session. A Claude Code card run or chat that's going takes your words at once. A run that's over carries on the same session with them. The other tools get them as a comment when their run ends.
- Open in Terminal opens Terminal on the session with its own command to look in (claude --resume, codex resume…), with your own settings. It's off while a run goes, as two at once would clash.
- Agents wear their provider's icon in Settings → Agents too.

## Binders for iPhone 2.4

- The Agents tab shows each agent as the Mac does: its icon and what it's doing, the strip of its cards and chats, and the session as the same terminal, every 2 seconds while a run goes.
- Write to it there: into a chat, or into a card's session, straight into a Claude Code run that takes it. The first time anything goes to an agent as it's set up now, Binders asks you first.
- A card that waits on you says so, with Open Card to answer or approve it. Stop ends a run.
- With a Mac before 0.13.0, the iPhone keeps the chat it had.

## Coding tools in the folder itself

- Codex, OpenCode, Copilot and Antigravity can now work in the folder itself, as Claude Code can: any folder, such as a workspace holding several repositories. Each run starts in the folder as it is, with no worktree. It changes your files there directly, Binders commits nothing, and one card runs in the folder at a time. One agent then serves every repository in the folder.

## Pull requests when they finish

- Turn on Open a pull request for an agent and Binders opens one when it finishes a card. The run still can't push: Binders pushes the branch and opens the pull request with your own git sign-in and GitHub's gh, never to the default branch or a main, master, trunk, develop, production or release, never forced, and not when the branch has nothing new. The card gets the pull request's link.
- Claude Code, and Codex in the folder itself, commit on a branch of their own and ask Binders for the pull request, one for each repository they changed. The other tools in a worktree get theirs from Binders after its commit on the card's branch.

## Folders as a tree

- Notes, Meetings and Captures show a binder's folders as a tree, as Finder does: a folder opens and closes where it is, with what's in it indented under it, and new things go into the one you're in.
- Something opened from elsewhere opens the folders it's in and scrolls to it. Collapse All is in each list's header and in the sidebar. What's open is kept across launches. Filtering or searching shows a flat list with each item's folder.

## Distill

- No repeats: Binders' model hears what's already been taken from a note, by agents and models, waiting for review, on the board or put aside, and leaves out items much like those, in any words. An agent asked to "Distill with…" hears the same through note_progress, and keeps what's new in a section that didn't change.
- Work items waiting for review are marked in the note with a dotted tint and a Proposed chip that opens the Distill list at the item.
- An agent's or the Manager's card can link back to the note and the passage it came from, and shows in the note.
- The card that asks an agent to distill a note now opens that note's tools, so the agent can read all of it and propose its items. A note too long for the card says how to read the rest.
- An item that waits on another that was left out as a repeat now waits on what it repeats.

## The Manager on a managed Mac

- Binders reads every place an organization's Claude Code settings can come from, and says why a run didn't start in plain words where it knows them (settings waiting for your approval in a terminal, not signed in, a Claude Code older than Binders needs).
- A request that fails offers Ask Again and Show Its Log. A run whose Binders tools didn't come up stops at once and says so.

## Fixes

- The Manager's "is on it" line shows a spinner in place of a red dot.
- OpenCode wouldn't start on a card whose worktree holds a Python virtual environment, as its interpreter links outside the worktree. That link now passes; any other link out of the worktree still stops it.
